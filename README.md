# Yandex Wave Discord Bot

Discord-бот, который играет станцию «Моя волна» Яндекс.Музыки в голосовом
канале одного сервера.

## 1. Что делает бот

- Подключается к голосовому каналу и запускает станцию «Моя волна».
- Автоматически подгружает следующий трек волны по мере воспроизведения.
  В буфере намеренно хранится только один трек вперёд — цепочка всё равно
  перезапрашивается после каждого выданного трека, поэтому больший запас
  быстро устаревает и не даёт волне оставаться максимально свежей.
- Управляется slash-командами: пауза/возобновление, пропуск трека,
  регулировка громкости, бас-буст с несколькими уровнями.
- Умеет искать трек по названию и запускать волну от него: сначала играет
  сам найденный трек, а следом — волна, построенная по нему. Когда под
  запрос подходит несколько треков, бот показывает до пяти самых подходящих
  списком и кнопки выбора под ним — прокручивать ничего не нужно.
- Держит в текстовом канале **одно живое сообщение-плеер** и обновляет его на
  месте, а не пишет новое на каждый трек. Сверху видно, какая волна играет
  («Моя волна» или «Моя волна по ⟨трек⟩»), ниже — обложка трека, под ней
  исполнитель, название и полоса прогресса, а снизу кнопки: пауза,
  следующий трек, поиск и отключение. Кнопки доступны тем, кто сидит в одном
  голосовом канале с ботом; когда бот никуда не подключён — всем, иначе
  волну некому было бы перезапустить.
- Показывает информацию о текущем треке и ближайшую очередь.
- Сам отключается от голосового канала после периода бездействия.
- При пропуске трека отправляет серверу фидбек и перезапрашивает
  последовательность «Моей волны», поэтому волна подстраивается под
  пропуски так же, как оригинальное приложение Яндекс.Музыки; недавно
  игравшие треки при этом не повторяются. Бот работает по тому же
  сессионному rotor-API, что и приложение: у прослушивания есть
  идентификатор сессии, а оценки уезжают тем же запросом, которым
  запрашивается следующая пачка треков, — так пропуск гарантированно
  успевает повлиять на подбор. Протокол описан в
  [`docs/rotor-session-api.md`](docs/rotor-session-api.md).
- Оценки «нравится»/«не нравится» бот сознательно не отправляет: он
  работает под одним аккаунтом Яндекса, и такая оценка осела бы в личной
  коллекции владельца токена, а не отражала бы вкус того, кто слушает.
- **Чат-рулетка (nekto.me) отключена.** Раньше бот умел заходить в
  голосовой канал, находить через сервис случайного собеседника и работать
  мостом между ним и каналом. Сейчас эта функция выключена в коде: ког
  рулетки не регистрируется в `bot/__main__.py`, команд `/roulette*` в
  Discord нет, соединений с nekto.me бот не открывает — независимо от
  значений `NEKTO_TOKEN`/`NEKTO_USER_AGENT`. Сам код рулетки
  (`bot/roulette.py`, `bot/cogs/roulette*.py`, `bot/nekto/`) оставлен в
  репозитории: чтобы вернуть функцию, достаточно восстановить импорт и
  регистрацию `RouletteCog` в `bot/__main__.py`.
- Умеет **распознавать русскую речь и выполнять голосовые команды**, пока
  подключён к голосовому каналу — офлайн, без отправки звука куда-либо ещё,
  через библиотеку `vosk`. Работает постоянно и не требует отдельной
  команды: достаточно обратиться к боту по имени («Катя, включи мою волну»,
  «Катя, следующий трек» и т. п.). Подробности, полный список команд, важное
  предупреждение о приватности и как скачать модель — раздел 7.

## 2. Требования

- Python 3.12 или новее.
- `ffmpeg`, доступный через `PATH` (или указанный явно через `FFMPEG_PATH`):
  - **Linux (Debian/Ubuntu):** `sudo apt install ffmpeg`
  - **Windows:** `winget install ffmpeg` (или скачать сборку с
    [ffmpeg.org](https://ffmpeg.org/download.html) и добавить `bin` в `PATH`)
- Аккаунт Яндекс.Музыки с активной подпиской. Без подписки «Моя волна» либо
  недоступна, либо отдаёт только превью треков вместо полных версий.
- Приложение бота, созданное в Discord Developer Portal.

## 3. Установка

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows
.venv\Scripts\activate

pip install -r requirements.txt
```

Для разработки (тесты, линтер): `pip install -r requirements-dev.txt`.

## 4. Получение Discord-токена

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications)
   и создайте приложение.
2. Перейдите в раздел **Bot** и нажмите **Reset Token**, чтобы получить токен
   бота. Сохраните его — он понадобится в `.env` как `DISCORD_TOKEN`.
3. Специальные intents **Server Members** и **Message Content** боту **не
   нужны** — не включайте их.
4. В разделе **OAuth2 → URL Generator** выберите scopes `bot` и
   `applications.commands`, а из прав бота — `Connect`, `Speak`,
   `Send Messages`, `Use Slash Commands`. Полученной ссылкой пригласите бота
   на сервер.

## 5. Авторизация в Яндекс.Музыке

Бот использует **неофициальный API** Яндекс.Музыки через библиотеку
`yandex-music`. Для доступа к аккаунту нужен OAuth-токен — **пароль от
аккаунта боту никогда не передаётся и нигде не хранится**.

### Основной способ: device flow

```bash
python scripts/get_token.py
```

Скрипт напечатает код и ссылку. Порядок действий:

1. Откройте напечатанную ссылку на любом устройстве (телефоне, ноутбуке —
   не обязательно на том же, где запущен скрипт).
2. Введите показанный код на странице Яндекса и подтвердите вход.
3. Скрипт сам дождётся подтверждения и выведет строку вида
   `YANDEX_MUSIC_TOKEN=<значение>` — добавьте её в `.env`.

Это отлично работает и на **headless-сервере по SSH**, потому что ввод кода
происходит на отдельном устройстве, а не в самом терминале сервера.

Есть флаг `--write-env`, который сам допишет токен в `.env` (по умолчанию
выключен и значение просто печатается в консоль), и `--timeout` для
изменения времени ожидания подтверждения (по умолчанию 300 секунд).

### Альтернатива

Токен также можно получить сторонними утилитами/расширениями, которые
извлекают его из уже авторизованной сессии браузера. **Никогда не вводите
логин и пароль от Яндекса в сторонние сайты или сервисы** — используйте для
этого только сам сайт `music.yandex.ru`.

### Срок действия токена

Токен, полученный через device flow, долгоживущий и не требует регулярного
обновления. Если доступ будет отозван вручную (Яндекс ID → Безопасность →
приложения с доступом к аккаунту), бот перестанет авторизовываться — в этом
случае просто перевыпустите токен тем же скриптом.

## 6. Авторизация в чат-рулетке (nekto.me) — функция отключена

> **Раздел неактуален, пока чат-рулетка выключена.** Ког рулетки не
> регистрируется (см. `bot/__main__.py`), поэтому заполнять `NEKTO_TOKEN` и
> `NEKTO_USER_AGENT` не нужно: бот их читает только чтобы замаскировать
> токен в логах, но никуда не передаёт. Шаги ниже сохранены на случай,
> если функцию решат вернуть.

Если она нужна, потребуется токен доступа к [nekto.me](https://nekto.me/) и
User-Agent того браузера, в котором этот токен был получен, — **сервис
сверяет их друг с другом**, токен и User-Agent от разных браузеров работать
не будут.

1. Откройте [nekto.me/audiochat](https://nekto.me/audiochat) в браузере и
   пройдите капчи (их три) — токен появляется в хранилище браузера только
   после этого.
2. Откройте консоль разработчика (F12 → вкладка **Console**) и выполните
   в ней:
   ```js
   JSON.parse(localStorage.getItem("storage_audio_v2")).user.authToken
   ```
   Токен лежит **не** под отдельным ключом `token`, а внутри объекта
   `storage_audio_v2` — простой `localStorage.getItem('token')` вернёт
   `null`. Если и эта команда даст `null` или ошибку, посмотрите, что вообще
   лежит в хранилище, через `Object.keys(localStorage)`: сервис мог
   переименовать ключ.
3. Скопируйте значение без кавычек в `.env` как `NEKTO_TOKEN`.
4. Там же, в консоли, выполните `navigator.userAgent` и скопируйте
   результат в `.env` как `NEKTO_USER_AGENT` **того же браузера и той же
   сессии**, где был получен токен.

**Токен со временем протухает** (сервис ограничивает срок его действия) —
когда рулетка перестанет подключаться, повторите эти шаги и обновите оба
значения в `.env`.

## 7. Распознавание речи и голосовые команды

Пока бот подключён к голосовому каналу (командой `/join`, `/wave`,
`/search` и т. п.), он постоянно слушает канал и распознаёт русскую речь —
никакой отдельной команды для этого не нужно. Всё распознавание идёт
**офлайн**, через библиотеку `vosk`: звук никуда за пределы машины, на
которой работает бот, не отправляется. Распознавание использует то же
самое голосовое соединение, что и воспроизведение музыки, и не мешает ему.

Функция включена по умолчанию и не зависит от `NEKTO_TOKEN`: без модели на
диске бот всё равно запускается и работает как обычный музыкальный бот,
просто голосовые команды не заработают (см. лог при старте — там будет
понятное предупреждение). Полностью отключить распознавание можно
переменной окружения `SPEECH_ENABLED=0` (см. раздел 8) — тогда модель не
грузится и ког голосового управления не подписывается на события плеера
вообще.

### Голосовые команды

Чтобы бот отреагировал, нужно обратиться к нему по имени в начале фразы.
Имён два и они равноправны — **«Катя»** и **«Гурген»**. Например:

| Пример фразы                        | Действие                                   |
|--------------------------------------|---------------------------------------------|
| «Катя, включи мою волну»            | Запустить «Мою волну» (как `/wave`).        |
| «Катя, следующий трек»              | Пропустить текущий трек (как `/skip`).      |
| «Катя, поставь на паузу»            | Поставить на паузу (как `/pause`).          |
| «Катя, продолжай»                   | Возобновить воспроизведение (как `/resume`).|
| «Катя, громкость пятьдесят»         | Установить громкость 50% (как `/volume`).   |
| «Катя, погромче» / «Катя, потише»   | Изменить громкость на ±20%.                 |
| «Катя, что играет»                  | Сказать, какой трек сейчас играет.          |
| «Катя, включи <исполнитель/трек>»   | Найти трек и запустить волну от него (как `/search`). |
| «Катя, отключись»                   | Отключиться от голосового канала (как `/leave`). |

Слово «трек» необязательно: «Катя, следующий» работает так же, как «Катя,
следующий трек». Вместо «Катя» в любой из фраз можно сказать «Гурген».

**Когда ждать реакции.** Бот отвечает примерно через 0.4 секунды после
того, как вы замолчали: именно столько он ждёт, прежде чем счесть фразу
законченной. Команды, которые ходят в API Яндекс.Музыки (запуск волны,
поиск, переключение трека), выполняются заметно дольше, поэтому бот
сначала присылает короткое «⏳ Слышу: …», а потом заменяет его итогом —
так видно, что команда принята, и не нужно повторять её вслух. Паузу
ожидания можно изменить константой `PHRASE_SILENCE_TIMEOUT` в
`bot/listening.py`: меньше — бот отзывается быстрее, но может разорвать
фразу на естественной паузе между словами.

**Почему второе имя устроено сложнее.** Слова «Гурген» нет в словаре малой
модели, и произнесённое имя она физически не может выдать как «гурген» —
вместо него приходит «гордин», «гардин», «мурген», а на медленной речи имя
и вовсе разваливается на два слова, «гор гин». Поэтому бот опознаёт второе
имя не по написанию, а по тому, как его реально слышит модель: набор
вариантов снят с синтезированной речи на трёх скоростях, все 24 записи
дошли до верной команды. Практическое следствие: **при смене модели
распознавания этот список стоит перепроверить** — у модели побогаче ошибки
будут другими, а «Гурген» она может знать и вовсе. С именем «Катя» такой
возни не нужно: его модель знает и выдаёт как есть.

**Имя можно произнести отдельной фразой.** Распознавание режет речь на
фразы по паузам, а обращение «Катя, следующий» люди обычно произносят
именно с паузой после имени — тогда до бота приезжают две отдельные фразы,
«катя» и «следующий». Поэтому один только оклик по имени открывает окно в
10 секунд, в течение которого следующая фраза **того же человека**
принимается как команда уже без повторного имени. Окно закрывается первой
же следующей фразой — неважно, оказалась она командой или нет, — чтобы
случайное «Катя?» не превращало в команды весь дальнейший разговор.

Распознавание не идеально (особенно с малой моделью по умолчанию, см. ниже)
и допускает небольшие опечатки в имени и формах слов, но не гарантирует
понимание любой формулировки — используйте фразы, близкие к примерам выше.
Если команды срабатывают через раз, чаще всего помогает модель покрупнее
(см. «Как скачать модель») и разговорный микрофон поближе ко рту: чем
чище звук, тем реже распознавание рвёт фразу посередине.
Если бота ещё нет в голосовом канале, а голосовая команда требует
подключения (например «включи мою волну»), он подключится к каналу того,
кто её произнёс.

### Предупреждение о приватности

**Пока бот подключён к голосовому каналу, он постоянно распознаёт речь
ВСЕХ участников этого канала**, а не только тех, кто обращается к нему по
имени — это нужно, чтобы вовремя заметить обращение «Катя, …» в потоке
обычного разговора. Сама расшифровка по умолчанию **никуда не публикуется**
— в текстовый канал уходят только короткие подтверждения выполненных
голосовых команд, и они не содержат распознанного текста целиком, только
краткое описание самой команды.

Полная публикация каждой распознанной фразы — отдельная отладочная
возможность, включаемая переменной `SPEECH_TRANSCRIPT=1` (см. раздел 8).
**Это именно отладочный режим, а не постоянная настройка**: при его
включении в текстовый канал уходит речь ВСЕХ участников голосового канала
целиком — не только тех фраз, что были обращены к боту, и не только у того,
кто отдаёт команды. Включать его на общем сервере без явного предупреждения
всех присутствующих не стоит, а после того как проблема, ради которой его
включили, разобрана — флаг стоит вернуть в `0`. В любом случае участникам
голосового канала стоит знать о работающем распознавании заранее, прежде
чем говорить при боте. Отключить распознавание совсем можно переменной
`SPEECH_ENABLED=0`.

### Бот плохо распознаёт речь: модель или связь?

Плохое распознавание выглядит одинаково в двух совершенно разных случаях:
модель не разобрала чистую речь — или до модели доехала речь с дырами,
потому что часть голосовых пакетов потерялась по дороге. По итоговому
тексту эти случаи не различить, поэтому есть отладочная запись: она
сохраняет на диск **ровно тот звук, который уходит в распознавание**, и
статистику потерь пакетов.

Укажите каталог в `.env` и перезапустите бота:

```
SPEECH_DEBUG_DIR=logs/speech-debug
```

Дальше зайдите в голосовой канал, скажите несколько команд, которые бот
понял неправильно, и **отключите бота от канала** («Катя, отключись» или
кнопка «Отключить») — файлы дописываются именно в этот момент. В каталоге
появится папка с меткой времени, а в ней:

| Файл                | Что внутри                                                    |
|----------------------|----------------------------------------------------------------|
| `speaker-<id>.wav`  | Звук каждого говорящего — тот самый, что слышала модель.       |
| `transcript.txt`    | Что модель из него разобрала, с отметками времени.             |
| `summary.txt`       | Сколько пакетов пришло и сколько потерялось, по каждому.       |

**Как читать результат.** Откройте `summary.txt` и послушайте WAV:

* **потери больше 1% в `summary.txt`** — дело в связи, модель ни при чём.
  Разрыв в нумерации пакетов — это именно потеря по дороге, а не пауза в
  речи: когда человек молчит, пакеты просто не отправляются, и нумерация
  остаётся сплошной. Смотрите в сторону сети сервера, где запущен бот;
* **потерь нет, но в записи ровный громкий треск** — дело в обработке
  звука внутри бота. Ровно так проявлялась ошибка извлечения звука из
  аудиокадра, из-за которой между кадрами каждые 20 мс вклинивался
  выравнивающий хвост буфера: запись становилась на 20% длиннее исходной
  речи и трещала, а распознавание давало одно слово из восьми. Ошибка
  исправлена (см. `frame_to_pcm` в `bot/nekto/audio.py` и тесты
  `tests/test_audio_frames.py`); если похожее повторится, первым делом
  сравните длительность записи с числом принятых пакетов из `summary.txt`
  — каждый пакет это ровно 20 мс, и заметное расхождение сразу указывает
  на обработку, а не на сеть;
* **звук рваный, слова «съедены» или речь звучит ускоренной** — потерянные
  куски не оставляют тишины, запись просто склеивается без них, и это
  хорошо слышно;
* **звук чистый, а текст в `transcript.txt` неверный** — дело в модели.
  Помогает модель покрупнее (см. ниже) и микрофон поближе ко рту.

Не забудьте убрать `SPEECH_DEBUG_DIR` после разбора: это запись чужой речи
на диск, и держать её включённой постоянно нельзя. Запись сама
останавливается через 10 минут на каждого говорящего (около 19 МБ),
предел меняется переменной `SPEECH_DEBUG_MAX_SECONDS`.

### Бот отвечает на голосовые команды

На каждую голосовую команду бот коротко откликается вслух — «Готово»,
«Переключаю», «Волна пошла», «Пока». На каждое действие заготовлено по
десятку с лишним реплик, выбирается случайная, и одна и та же фраза не
повторяется два раза подряд — иначе на коротком списке случайность
слышится как заевшая пластинка.

**Ответ звучит одновременно с выполнением команды**, а не после него:
трек переключается в тот же момент, когда бот говорит «Переключаю».
Единственное исключение — отключение от канала: договорить после выхода
физически невозможно, поэтому там бот сначала прощается и только потом
уходит.

**Неудачи бот тоже проговаривает** — иначе, отдав команду голосом, о них
не узнать, не заглянув в чат. Если команда не выполнилась, звучит вводная
и сама причина: «Не сложилось. Поиск треков сейчас недоступен.» Если поиск
отработал, но ничего не нашёл, — это не сбой, и фразы для него отдельные:
«Ничего похожего. По запросу группа кино.» Текст в чате при этом остаётся
полным; вслух повтор «ничего не найдено» после «ничего похожего» звучал бы
тавтологией, поэтому произносимая фраза короче написанной.

Озвучивание неудачи никогда не мешает самой неудаче дойти до человека:
если синтез выключен, модель ещё не готова или сам синтез сбоит, причина
всё равно приходит текстом в чат, как раньше.

Реплики намеренно безличные («готово», «переключаю», а не «сделала») —
у бота два имени, женское и мужское, и говорить о себе в роде он не должен.
Отключается всё это переменной `VOICE_REPLIES=0`, не трогая остальной
синтез (`/say` и «повтори» продолжат работать).

**Что бот умеет выговорить.** Синтез принимает только русские буквы, а на
цифре или латинице падает. Поэтому перед произнесением текст приводится к
произносимому: цифры проговариваются словами («50» → «пятьдесят»), латиница
читается по звучанию («Nirvana» → «нирвана»), остальные знаки отбрасываются.
Транслитерация грубая — важно, чтобы бот сказал похоже, а не молчал. Поэтому
же в подтверждении `/say` показывается то, что бот произнёс на самом деле, а
не исходное написание.

### Бот говорит: команда «повтори»

Бот умеет не только слушать, но и произносить текст вслух в голосовом
канале — голосом или текстовой командой:

- голосом: «Катя, повтори привет всем», «Катя, повтори за мной я бот»,
  «Катя, скажи хорошего вечера»;
- текстом: `/say <текст>`.

**Музыка на время фразы приостанавливается**, а после — продолжается ровно
с того места, где её прервали: трек не проматывается под голос. Если бот
стоял на паузе, он скажет фразу и вернётся на паузу.

Синтез тоже офлайн, через `vosk-tts` — текст никуда не отправляется.
Модель (около 130 МБ) скачивается **сама при первой произнесённой фразе**,
поэтому первая фраза после установки бота потребует ожидания, а дальше
синтез идёт примерно в 18 раз быстрее реального времени — задержки не
чувствуется. Длина фразы ограничена 300 символами: бот занимает голосовой
канал и глушит музыку на всё время произнесения.

Голос выбирается настройкой `TTS_SPEAKER_ID` (0..4 у многоголосой модели),
а выключается синтез целиком через `TTS_ENABLED=0` (см. раздел 8).

### Как скачать модель

1. Скачайте архив с русской моделью:
   [vosk-model-small-ru-0.22.zip](https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip)
   (около 45 МБ, распаковывается в ~88 МБ).
2. Распакуйте архив так, чтобы получился каталог
   `models/vosk-model-small-ru-0.22` рядом с `bot/` (в корне проекта). Путь
   можно изменить переменной `SPEECH_MODEL_PATH` (см. раздел 8).
3. Перезапустите бота — при старте в логе будет видно, найдена модель или
   нет.

Малая модель (`vosk-model-small-ru-0.22`) быстрая и лёгкая, но не самая
точная. Для лучшего качества распознавания на [странице моделей
Vosk](https://alphacephei.com/vosk/models) есть более крупные русские
модели (например, `vosk-model-ru-0.42`, около 2 ГБ) — они точнее, но
требуют заметно больше памяти и процессорного времени на распознавание.
Чтобы использовать другую модель, скачайте и распакуйте её в отдельный
каталог и укажите путь к нему в `SPEECH_MODEL_PATH`.

## 9. Запуск

Запускать нужно интерпретатором того окружения, куда установлены зависимости.
Если использовалось виртуальное окружение (`.venv`), сначала активируйте его:

```bash
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

python -m bot
```

Либо без активации, указав интерпретатор окружения напрямую:

```bash
# Windows
.venv\Scripts\python.exe -m bot
# Linux / macOS
.venv/bin/python -m bot
```

Запуск глобальным `python` при зависимостях в `.venv` приводит к ошибке
`RuntimeError: PyNaCl library needed in order to use voice` при попытке зайти
в голосовой канал (см. раздел «Устранение неполадок»). На Windows учтите
также, что `python3` — это, как правило, заглушка Microsoft Store, а не
интерпретатор; используйте `python`.

Пример unit-файла systemd для запуска на сервере (`/etc/systemd/system/yandex-wave-bot.service`):

```ini
[Unit]
Description=Yandex Wave Discord Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/yandex-wave-bot
EnvironmentFile=/opt/yandex-wave-bot/.env
ExecStart=/opt/yandex-wave-bot/.venv/bin/python -m bot
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now yandex-wave-bot
```

### 9.1. Запуск в Docker

Альтернатива systemd: в репозитории есть `Dockerfile` и `docker-compose.yml`.
Образ основан на `python:3.12-slim-bookworm`, внутрь ставится `ffmpeg` и
зависимости из `requirements.txt`, процесс работает не от root.

Что **не** попадает в образ и монтируется томами:

| Что | Куда | Почему |
|-----|------|--------|
| `.env` | `env_file` | секреты не должны лежать в слоях образа |
| `./models` | `/app/models` (ro) | модель распознавания весит около 2 ГБ |
| `./logs` | `/app/logs` | логи должны пережить пересоздание контейнера |
| том `vosk-cache` | `~/.cache/vosk` | модель синтеза скачивается сама, качать её заново после каждой пересборки незачем |

Перед первым запуском на сервере нужны три вещи: файл `.env` рядом с
`docker-compose.yml` (см. раздел 8), скачанная модель распознавания в
`./models` (см. раздел 7) и установленный Docker с плагином Compose.

```bash
docker compose up -d --build
docker compose logs -f
```

Обновление после правок кода — та же команда: `docker compose up -d --build`.
Остановка — `docker compose down` (тома при этом сохраняются).

Про память: с моделью `vosk-model-ru-0.42` контейнеру нужно около 3 ГБ, а
с включённым нейросетевым переоцениванием (каталог `rnnlm` внутри модели) —
около 5.5 ГБ. На машине с 2 ГБ бот будет убит OOM-киллером ещё на загрузке
модели. Ограничение памяти в `docker-compose.yml` намеренно не задано:
жёсткий лимит ниже реальной потребности превратил бы понятный отказ при
старте в необъяснимые перезапуски.

Если голосовые команды не нужны вовсе, поставьте `SPEECH_ENABLED=0` — тогда
модель не грузится и контейнеру хватает нескольких сотен мегабайт.

нет: чат-рулетка отключена в коде (см. раздел 6).

### Голосовые команды («Катя, …»)

Отдельной slash-команды для распознавания речи нет — оно работает
постоянно, пока бот подключён к голосовому каналу. Чтобы бот отреагировал,
фраза должна начинаться с обращения к нему по имени: **«Катя»** или
**«Гурген»** — имена равноправны. Подробности, ограничения и
предупреждение о приватности — в разделе 7.

| Пример фразы                                | Действие                                                        |
|----------------------------------------------|------------------------------------------------------------------|
| «Катя, включи мою волну»                    | Запустить «Мою волну» — как `/wave`.                             |
| «Катя, включи волну от <исполнитель/трек>»  | Найти трек и запустить волну от него.                            |
| «Катя, включи <исполнитель/трек>»           | То же самое: найти и запустить. Синонимы глагола — «поставь», «найди», «сыграй», «запусти». |
| «Катя, следующий» / «Катя, следующий трек»  | Пропустить текущий трек — как `/skip`. Слово «трек» необязательно. Синонимы: «дальше», «переключи», «пропусти». |
| «Катя, поставь на паузу»                    | Поставить на паузу — как `/pause`. Синонимы: «пауза», «останови», «стоп», «замолчи». |
| «Катя, продолжай»                           | Возобновить воспроизведение — как `/resume`. Синонимы: «возобнови», «играй дальше». |
| «Катя, громкость пятьдесят»                 | Установить громкость 50% — как `/volume`. Число говорится словами, поддерживается 0–100. |
| «Катя, погромче» / «Катя, потише»           | Изменить громкость на ±20%.                                      |
| «Катя, что играет»                          | Назвать текущий трек — как `/nowplaying`. Синонимы: «кто поёт», «что за песня». |
| «Катя, отключись»                           | Отключиться от голосового канала — как `/leave`. Синонимы: «выключись», «уйди», «хватит». |
| «Катя, повтори привет всем»                 | Произнести фразу голосом — как `/say`. Синонимы: «повтори за мной …», «скажи …», «произнеси …». Музыка на время фразы приостанавливается (см. раздел 7). |

Команды понимаются в любом падеже («следующий трек» и «следующего трека» —
одно и то же), порядок слов внутри команды значения не имеет («поставь на
паузу» = «на паузу поставь»), а имя распознаётся и в других формах — «Кате»,
«Катю», «Катька».

**Имя может стоять где угодно во фразе**, а не только в начале: распознавание
отдаёт длинную реплику одним куском, и фраза «…а потом говорю, Катя, включи
следующую песню» должна работать. Командой считается всё, что сказано после
ПОСЛЕДНЕГО упоминания имени. Чтобы обычный разговор о боте не превращался в
команды, слова в прошедшем времени командными не считаются: «я вчера Кате
включил эту песню» и «Катя закончила работу» бот пропускает мимо ушей, а
«Катя, включи» — выполняет. Различие грубое (по окончанию слова), но
повелительные формы в русском так не оканчиваются, поэтому на практике оно
работает.

В отличие от `/search`, голосовой поиск **ничего не переспрашивает**: бот
берёт самый первый найденный трек и сразу запускает волну от него, называя
в подтверждении исполнителя и название — чтобы было видно, верно ли он
расслышал запрос. Меню выбора из нескольких треков остаётся только там, где
есть кому нажимать: у команды `/search` и у кнопки «Поиск» под сообщением
плеера.

### Кнопки

Под сообщением-плеером «Моей волны» всегда есть строка кнопок — то же
самое, что и команды выше, но без набора текста:

| Кнопка                     | Действие                                                |
|-----------------------------|----------------------------------------------------------|
| ⏸️ «Пауза» / ▶️ «Продолжить» | Пауза и продолжение; подпись меняется по состоянию.      |
| ⏭️ «Следующий»              | Пропустить текущий трек.                                 |
| 🔍 «Поиск»                  | Открыть окно поиска трека и запустить волну от него.     |
| 🔌 «Отключить»              | Остановить воспроизведение и отключиться от канала.      |

У сообщения-статуса чат-рулетки — свои две кнопки: ⏭️ «Следующий»
(перейти к другому собеседнику) и 🔌 «Стоп» (завершить рулетку).

На уровнях `low`/`medium`/`high` усиление баса ограничивается лимитером,
чтобы звук оставался чистым. На уровне `extreme` лимитер намеренно
**отключён** — низкие частоты уходят в клиппинг при воспроизведении.
Это ожидаемое поведение максимального уровня («басы должны быть громче
любой ценой»), а не дефект.

Как и у «Моей волны», у чат-рулетки есть своё **живое сообщение-статус**:
идёт поиск / собеседник найден / собеседник покинул разговор / рулетка
остановлена, с кнопками «Следующий» и «Стоп» под ним. Кнопки доступны тем,
кто сидит в одном голосовом канале с ботом. «Моя волна» и чат-рулетка
используют одно голосовое соединение сервера и не могут звучать
одновременно: `/roulette` сама останавливает волну перед запуском. Обратного
(автоматической остановки рулетки командой `/wave`/`/play`) пока не сделано
— это известное ограничение.

Распознавание речи, в отличие от чат-рулетки, **не** открывает отдельное
голосовое соединение — оно делит то же самое соединение, что и «Моя волна»,
поэтому музыка и голосовые команды работают одновременно без ограничений.
А вот с чат-рулеткой распознавание по-прежнему несовместимо, по той же
причине, что и волна: у рулетки своё отдельное соединение, и запуск
`/roulette` останавливает волну (а вместе с ней — и распознавание, работавшее
на её соединении).

## 11. Логирование

Логи пишутся в `logs/bot.log` с ротацией (до 5 МБ на файл, 3 архивных копии)
и дублируются в консоль. Уровень логирования регулируется переменной
`LOG_LEVEL`. Секреты (токены Discord, Яндекс.Музыки и чат-рулетки)
маскируются специальным фильтром логирования и **никогда** не попадают ни в
логи, ни в сообщения бота в Discord.

Тот же фильтр ограничивает длину строки лога 500 символами, дописывая
пометку с исходной длиной. Это нужно потому, что API Яндекса при ответе
`429` кладёт в текст исключения целую HTML-страницу в несколько килобайт, и
без ограничения одна такая запись делала лог нечитаемым. Трейсбеки не
обрезаются — они нужны для диагностики целиком.

## 12. Безопасность

- Файл `.env` уже добавлен в `.gitignore` — не коммитьте его.
- Токены не логируются и не выводятся ботом в чат ни при каких условиях
  (единственное место, где токен печатается в открытом виде, — вывод
  скрипта `scripts/get_token.py`, предназначенного для однократного
  копирования значения в `.env`).
- При подозрении на компрометацию — перевыпустите токены: сбросьте токен
  бота в Discord Developer Portal, получите новый токен Яндекс.Музыки через
  `scripts/get_token.py`, а для чат-рулетки — повторите шаги раздела 6.
- Библиотека `yandex-music` использует неофициальный API Яндекс.Музыки.
  Используется на свой риск, без каких-либо гарантий; это не официальный
  продукт Яндекса.
- Распознавание речи — офлайн (звук не отправляется никуда за пределы
  машины бота), но включено по умолчанию и работает постоянно, пока бот
  подключён к голосовому каналу: бот слушает речь всех участников этого
  канала, а не только тех, кто к нему обращается. Обязательно прочитайте
  предупреждение о приватности в разделе 7 и предупредите участников
  сервера заранее; полностью отключить функцию можно переменной
  `SPEECH_ENABLED=0`.

## 14. Устранение неполадок

| Проблема                                | Возможная причина и решение                                                                 |
|-------------------------------------------|-----------------------------------------------------------------------------------------------|
| `ffmpeg не найден`                        | Установите ffmpeg и убедитесь, что он в `PATH`, либо укажите путь в `FFMPEG_PATH`.             |
| Бот заходит в канал, но молчит            | Проверьте права бота `Connect`/`Speak` на канал и что установлен `PyNaCl` (см. `requirements.txt`). |
| `RuntimeError: PyNaCl library needed in order to use voice` при `/wave`, `/play` или `/join` | Бот запущен интерпретатором, в котором нет PyNaCl — чаще всего глобальным `python` при зависимостях в `.venv`. Запустите из окружения проекта (см. раздел «Запуск») либо установите зависимости в текущее окружение: `pip install -r requirements.txt`. |
| «Моя волна» сейчас недоступна             | Проверьте, что на аккаунте активна подписка Яндекс.Музыки, и что `YANDEX_MUSIC_TOKEN` не истёк — перевыпустите его скриптом `scripts/get_token.py`. |
| Slash-команды не появляются в Discord     | Убедитесь, что `GUILD_ID` в `.env` верный, и полностью перезапустите (перезайдите) клиент Discord. |
| В логе `BadRequestError: condition is not met` от фидбек-вызовов rotor | Это НЕ ожидаемое поведение. Библиотека `yandex-music` шлёт фидбек как форму (`x-www-form-urlencoded`), а сервер Яндекс.Музыки принимает только JSON, поэтому бот собирает запросы к ротору вручную и отправляет их в JSON (см. `YandexMusicClient` в `bot/yandex/client.py`). Если ошибка снова появится в логах — значит API Яндекса изменилось, и обход нужно пересмотреть, сверившись с [`docs/rotor-session-api.md`](docs/rotor-session-api.md). |
| Фидбек волны молча не доходит, а в логе — обрыв соединения вместо ответа сервера | Скорее всего, из пути запроса пропал завершающий слэш: сессионные эндпоинты фидбека (`/rotor/session/<id>/feedbacks/`) без него не отвечают `404`, а рвут TCP-соединение. Слэш в коде намеренный, убирать его нельзя — подробности в [`docs/rotor-session-api.md`](docs/rotor-session-api.md). |
| В логе `NetworkError: Unknown HTTPError (429)` | Яндекс временно ограничил доступ из-за слишком частых запросов (обычно это следствие отладочных прогонов, а не обычной работы бота: на трек приходится всего несколько запросов). Воспроизведение при этом не прерывается — неудачный фидбек и неудачное обновление цепочки логируются и пропускаются. Достаточно подождать несколько минут. |
| Команд `/roulette*` нет в Discord            | Так и задумано: чат-рулетка отключена в коде, ког не регистрируется (см. лог при старте: «Чат-рулетка (nekto.me) отключена в коде…» и раздел 6). Заполнение `NEKTO_TOKEN` этого не меняет. |
| Голосовые команды («Катя, …») не работают, в логе предупреждение про модель распознавания речи | Модели нет по пути `SPEECH_MODEL_PATH` (по умолчанию `models/vosk-model-small-ru-0.22`). Скачайте и распакуйте модель по инструкции в разделе 7, затем перезапустите бота — в логе при старте видно, найдена ли модель. |
| Голосовые команды не работают, а в логе ничего похожего на ошибку | Проверьте `SPEECH_ENABLED` в `.env` — возможно, распознавание явно выключено (`SPEECH_ENABLED=0`, см. раздел 8). |
| `/roulette` падает с ошибкой подключения к голосовому каналу, когда играет «Моя волна» | Ожидаемое поведение: «Моя волна» и чат-рулетка делят одно голосовое соединение сервера и не могут работать одновременно (см. раздел 10). `/roulette` сама останавливает волну перед запуском, а вот `/wave` поверх уже идущей `/roulette` — нет; сначала остановите её командой `/roulette_stop`. Распознавание речи в этом ограничении не участвует — оно делит соединение с волной, а не отдельное. |
